> 这是一篇随博客搭建附带的使用指南，不是站主过去经历的代写。开始写作后，可以修改或删除它。

一个博客不必在第一天就装满。先有一块舒服的地方，再慢慢往里面添东西。

## 写下第一篇文章

在仓库的 `_posts` 文件夹里新建 Markdown 文件。文件名用日期开头，例如 `2026-09-20-my-first-post.md`。

在文件最上方写上文章信息，正文接在后面：

```yaml
---
title: "我的第一篇文章"
description: "用一句话介绍这篇文章。"
date: 2026-09-20 10:00:00 +0800
tags: [随记]
---
```

这里的日期只是格式示例。正式发布时请改成实际日期；未来日期的文章默认不会发布。

标题、摘要和标签会自动出现在首页、归档和搜索中，不需要手动修改文章列表。

## 用 Markdown 专心写内容

普通段落直接写即可。用 **粗体** 强调重点，用 *斜体* 留下旁注，用 `行内代码` 标记一个变量。

### 放一段代码

代码围栏后写上语言名称，就会获得语法高亮。代码块右上角有复制按钮。

```python
def grow(idea: str) -> str:
    """从一个小小的想法开始。"""
    return f"今天，给 {idea} 一点时间。"

print(grow("我的个人博客"))
```

### 整理一张表格

| 想做的事 | 修改的位置 |
| :--- | :--- |
| 写文章 | `_posts/` |
| 改站名、描述和链接 | `_config.yml` |
| 改首页文案 | `index.html` |
| 完善自我介绍 | `about.html` |
| 展示项目 | `lab.html` |
| 修改配色与排版 | `assets/style.css` |

### 插入图片

把你有权使用的图片放进 `assets/images/`，再用 Markdown 引用。替代文字能帮助使用屏幕阅读器的读者理解图片。

```markdown
![图片的简短描述](/assets/images/your-image.webp)
```

上面的路径是写法示例，需要先添加真实图片。

## 让这个空间更像你

首页不用塞满所有东西。可以先改一句欢迎语、补几句自我介绍，然后放一个确实做过的小项目。

实验室里已经有一个可以玩的生成艺术实验：改变种子，让曲线长成不同的花。它不依赖外部接口，也不需要账号。

配色集中在 CSS 文件顶部。修改 `--accent` 就能给整个站换一个主色。深色主题也有独立的配色变量。

## 关于发布和草稿

把修改提交到 `master` 后，GitHub Pages 会按照仓库的发布设置构建和发布。构建结果可以在仓库的 Actions 页面查看。

尚未写完的文章可以放在 `_drafts/`。**草稿不显示在网站上，不代表它是私密的**：这个仓库是公开仓库，里面的草稿源文件同样公开。不要提交密码、账户信息或不准备公开的文字。

## 不用一次完成

第一篇可以只是一次排错、一段阅读记录，或一个今天还没想清楚的问题。

让它保持未完成，也保持生长。
